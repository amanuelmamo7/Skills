# Skill Evals

The intake checklist answers *"is this skill safe to trust?"* Evals answer a different
question: *"does this skill actually change what the agent does?"* A skill that scores no
better than its no-skill baseline is a candidate to cut or rewrite.

Pattern adopted from [hedera-dev/hedera-skills](https://github.com/hedera-dev/hedera-skills)
(2026-11-07), adapted to this repo's Python tooling and privacy rules.

## Layout

| File | Role |
|---|---|
| `skills/<id>/evals/spec.json` | Source of truth: prompts + structured checks. Edit this. |
| `skills/<id>/evals/evals.json` | Generated by `tools/compile_evals.py` (runs inside `tools/build.py`). Never hand-edit. |
| `agent-skills-eval.yaml` | Runner config: target model, judge model, baseline on. |

A skill with a spec shows ✓ in the dispatcher.

## Writing a spec

```json
{
  "skill_name": "<folder name>",
  "evals": [
    {
      "id": 0,
      "prompt": "Realistic request + any fixture data the skill would normally fetch",
      "expected_output": "One sentence describing a passing answer",
      "checks": [
        {"name": "short-id", "type": "rubric", "rubric": "The output ..."}
      ]
    }
  ]
}
```

Check types: `contains`, `regex`, `absent` (must NOT appear), `rubric` (judge-only).
Every check compiles to one plain-English assertion graded by the judge model; write
`rubric` text whenever the auto-generated sentence would be vague.

Write checks for the skill's **hard rules**, not its style, and include at least one
**pressure case** (the user pushing the agent to break a rule) and one **missing-data
case** (no live data available, so the right answer is honesty, not invention).

## Running

```bash
python3 tools/compile_evals.py
set -a && source .env && set +a      # OPENAI_API_KEY = OpenRouter key; .env is gitignored
npx agent-skills-eval@0.1.1 --config agent-skills-eval.yaml --include "analyst-house-style"
```

The runner is pinned to `agent-skills-eval@0.1.1` (reviewed 2026-11-07). Re-review before
bumping the version, and re-check the model slugs in the config when models are retired.

## Rules

- **Fictional fixtures only.** No real names, clients, matters, emails, or accounts. This
  repo is public, and eval prompts, skill text, and outputs go to the configured provider.
- **Private skills keep private evals.** Skills on the privacy sweep's never-publish list
  keep their `evals/` next to their private source, never in this repo.
- Target and judge should be different models so a skill isn't graded by its own author.
- Prioritize skills whose failures cost something: legal, financial, job applications,
  anything that sends, drafts, or schedules on the user's behalf.
